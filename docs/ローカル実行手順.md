# ローカルで動かす手順 & Windows Defender について

このアプリはインターネット上のサーバを使いません。起動すると PC 内部だけで小さな
Web サーバが立ち上がり、既定ブラウザで画面が開きます。データ(氏名・生年月日等)は
PC 内の SQLite ファイルにのみ保存され、外部送信は一切行いません。

動かす方法は 2 つあります。

| 方法 | 向いている場面 | Python の要否 | Defender の心配 |
|---|---|---|---|
| **A. ソースから実行(venv)** | 自分の PC で開発・検証する | 必要 | ほぼ無し(推奨) |
| **B. 配布 exe を実行** | Python の無い施設 PC に配る | 不要 | SmartScreen 警告あり(後述) |

---

## 方法A. ソースから実行(推奨・最も確実)

### 前提
- Python 3.10 以上(推奨 3.12)。確認: `python --version`
- 未インストールなら https://www.python.org/downloads/windows/ から入れる。
  インストーラで **「Add python.exe to PATH」にチェック**を入れること。

### 手順(Windows / PowerShell または コマンドプロンプト)

```powershell
REM 1. ソースを取得(git がある場合)
git clone https://github.com/piroshi1989/status-report-app.git
cd status-report-app

REM  git が無ければ GitHub の「Code > Download ZIP」で落として展開し、そのフォルダへ cd

REM 2. 仮想環境を作成して有効化
python -m venv .venv
.venv\Scripts\activate

REM 3. 依存をインストール
pip install -r requirements.txt

REM 4. 起動(自動でブラウザが開く)
python run.py
```

### 手順(WSL / Linux / macOS)

```bash
git clone https://github.com/piroshi1989/status-report-app.git
cd status-report-app
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python run.py
```

起動すると次のように表示され、少し待つと既定ブラウザで画面が開きます。

```
========================================================
  状況報告書作成アプリ
  http://127.0.0.1:53421      ← ポート番号は毎回変わります
  終了するにはこのウィンドウを閉じるか Ctrl+C を押してください。
========================================================
```

- ブラウザが自動で開かない場合は、表示された `http://127.0.0.1:...` のアドレスを
  ブラウザのアドレス欄に貼り付けてください。
- **終了**: この黒いウィンドウ(ターミナル)で `Ctrl + C`、またはウィンドウを閉じる。
- 2 回目以降は `.venv\Scripts\activate` してから `python run.py` だけで起動できます。

> WSL で起動して Windows 側のブラウザで開きたい場合は、WSL 側では自動で開かないことが
> あります。表示された `http://127.0.0.1:<ポート>` を Windows のブラウザに貼れば開けます。

### データの保存場所とバックアップ
- すべてのデータは `data/status_report.db`(SQLite 単一ファイル)に入ります。
- **バックアップ**: アプリ終了後にこのファイルをコピーするだけ。
- 別の場所に置きたい場合は環境変数で変更できます(下表)。

| 環境変数 | 既定 | 用途 |
|---|---|---|
| `STATUS_REPORT_DB` | `data/status_report.db` | DB ファイルの場所 |
| `STATUS_REPORT_OUTPUT_DIR` | `output/` | 一括 PDF の保存先 |
| `STATUS_REPORT_PORT` | 自動 | ポート番号を固定したいとき |
| `STATUS_REPORT_NO_BROWSER` | (未設定) | `1` にするとブラウザを自動で開かない |

PowerShell での指定例:
```powershell
$env:STATUS_REPORT_PORT=8000
python run.py
```

## 方法B. 配布 exe を実行

### exe の入手
- GitHub でタグ(`v1.0.0` など)を push すると、GitHub Actions が Windows 用 exe を
  自動ビルドして Releases に添付します。そこから `状況報告書アプリ.exe` をダウンロードします。
- 自分でビルドする場合(Windows + Python 環境):
  ```powershell
  pip install -r requirements-dev.txt
  pyinstaller status_report.spec
  REM  dist\状況報告書アプリ.exe が生成される
  ```

### 実行
1. `状況報告書アプリ.exe` をダブルクリック。
2. 黒いコンソール窓が開き、少し待つと既定ブラウザで画面が開きます。
3. 終了はコンソール窓を閉じるか `Ctrl + C`。
4. DB(`data/`)と PDF(`output/`)は **exe と同じフォルダ**に作られます。
   → 書き込み可能なフォルダ(デスクトップ等)に置いてください。`Program Files` 直下は避ける。

## Windows Defender / SmartScreen について(方法B の注意)

結論から言うと、**方法A(ソース実行)なら Defender の心配はほぼありません**。
配布 exe(方法B)では、署名していないため次の 2 種類の反応が起こり得ます。

### 1. SmartScreen の警告(ほぼ確実に出る・ブロックではない)

初回起動時に青い画面で
**「WindowsによってPCが保護されました」** が出ます。これはウイルス判定ではなく、
「署名が無く、まだ実績(ダウンロード数)の少ない exe です」という**評価ベースの警告**です。

- 回避手順: **「詳細情報」→「実行」** をクリックすれば起動できます。
- 同じ exe なら、一度実行を許可すればその PC では以降出ません。

### 2. Defender ウイルス対策の誤検知(出る可能性がある)

PyInstaller で作った exe は、内部で自身を一時展開する構造がマルウェアと似ているため、
Defender のヒューリスティック検知で **誤って** `Wacatac`/`Zusy` 等の名前で
隔離されることが**まれにあります**(必ず出るわけではありません)。当アプリは
外部通信もマクロ実行もしない素の Python アプリで、実害はありません。

**このアプリで既に行っている対策:**
- **UPX 圧縮を無効化**(`status_report.spec` で `upx=False`)。UPX は誤検知の主要因のため外しています。

**それでも検知される場合の対策(効果が高い順):**

1. **方法A(ソース実行)に切り替える** — exe を使わないので誤検知そのものが起きません。
   施設 PC に Python を入れられるなら、これが最も確実です。
2. **コード署名証明書で署名する** — OV/EV コード署名証明書で署名すると SmartScreen の
   実績も貯まり、警告・誤検知ともに大きく減ります(証明書は有償)。
   署名する場合は `status_report.spec` の `codesign_identity` 等ではなく、
   Windows では `signtool` でビルド後の exe に署名します。
3. **Microsoft に誤検知を報告する** —
   https://www.microsoft.com/en-us/wdsi/filesubmission に exe を提出すると、
   数日で定義が更新され検知されなくなります(社内配布前に一度出しておくと安心)。
4. **onefile ではなく onedir でビルドする** — 単一 exe をやめてフォルダ配布にすると
   誤検知率が下がります。`status_report.spec` の `EXE(...)` の後に `COLLECT(...)` を
   追加する構成に変えます(単一ファイルの手軽さは失われます)。
5. **Defender の除外設定を追加する**(社内管理 PC 向け) —
   「Windows セキュリティ > ウイルスと脅威の防止 > 除外の追加」で
   配置フォルダを除外します。組織のポリシーに従ってください。

### まとめ

| 心配 | 方法A(ソース) | 方法B(exe・未署名) | 方法B(exe・署名済み) |
|---|---|---|---|
| SmartScreen 警告 | 出ない | 出る(「詳細情報→実行」で回避) | ほぼ出ない |
| Defender 誤検知 | 起きない | まれに起きる | ほぼ起きない |
| 施設 PC に Python 必要 | 必要 | 不要 | 不要 |

社内・施設への正式配布まで行うなら、**コード署名証明書の取得**を検討してください。
まず試すだけなら **方法A** が手間もリスクも最小です。
